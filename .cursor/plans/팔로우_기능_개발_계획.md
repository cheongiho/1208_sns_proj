# 팔로우 기능 개발 계획

## 개요

PRD.md의 팔로우 기능 요구사항과 기존 좋아요 기능 패턴을 기반으로 팔로우/언팔로우 기능을 구현합니다. FollowButton 컴포넌트를 생성하고, 팔로우 API를 구현하며, ProfileHeader에 통합합니다.

## 현재 상태

- ✅ 데이터베이스: `follows` 테이블이 생성되어 있음 ([supabase/migrations/db.sql](supabase/migrations/db.sql))
  - `follower_id`: 팔로우하는 사람 (현재 사용자)
  - `following_id`: 팔로우받는 사람 (대상 사용자)
  - UNIQUE 제약조건: 중복 팔로우 방지
  - CHECK 제약조건: 자기 자신 팔로우 방지
- ✅ 타입 정의: `Follow` 타입이 정의되어 있음 ([lib/types.ts](lib/types.ts))
- ✅ 뷰: `user_stats` 뷰에 `followers_count`, `following_count` 포함
- ✅ 좋아요 기능: 유사한 패턴의 API 및 컴포넌트가 구현되어 있음 (참고용)
- ❌ 팔로우 API: POST/DELETE /api/follows 아직 구현되지 않음
- ❌ FollowButton 컴포넌트: 아직 구현되지 않음
- ❌ ProfileHeader: 아직 구현되지 않음 (TODO 8번과 연관)

## 구현할 항목

### 1. API 라우트 구현

#### 1-1. 팔로우 추가 API
**파일**: `app/api/follows/route.ts` (새 파일 생성)

- POST 메서드로 팔로우 추가 처리
- Clerk 인증 검증 (`auth()` 사용)
- 요청 본문에서 `followingId` 파싱 (팔로우받는 사람의 Supabase user_id)
- Clerk user ID를 Supabase user_id로 변환 (follower_id)
- 자기 자신 팔로우 방지 검증 (follower_id !== following_id)
- 중복 팔로우 방지 (UNIQUE 제약조건 활용)
- follows 테이블에 레코드 삽입
- 성공/실패 응답 반환
- 에러 처리 (인증 실패, 자기 자신 팔로우, 중복 팔로우, DB 에러 등)

**요청 형식**:
```typescript
POST /api/follows
{
  "followingId": "uuid" // 팔로우받는 사람의 Supabase user_id
}
```

**응답 형식**:
```typescript
{
  success: true,
  data: {
    id: string,
    follower_id: string,
    following_id: string,
    created_at: string
  }
}
```

**참고 패턴**: [app/api/likes/route.ts](app/api/likes/route.ts)의 POST 함수 구조를 참고

#### 1-2. 팔로우 제거 API
**파일**: `app/api/follows/route.ts` (동일 파일에 DELETE 함수 추가)

- DELETE 메서드로 팔로우 제거 처리
- Clerk 인증 검증
- 요청 본문에서 `followingId` 파싱
- Clerk user ID를 Supabase user_id로 변환 (follower_id)
- follows 테이블에서 레코드 삭제
- 성공/실패 응답 반환
- 에러 처리

**요청 형식**:
```typescript
DELETE /api/follows
{
  "followingId": "uuid" // 언팔로우할 사람의 Supabase user_id
}
```

**응답 형식**:
```typescript
{
  success: true
}
```

**참고 패턴**: [app/api/likes/route.ts](app/api/likes/route.ts)의 DELETE 함수 구조를 참고

#### 2-2. 버튼 상태 및 스타일

**미팔로우 상태**:

- Hover: 약간 어두운 파란색 (`#0095f6/90`)

**팔로우 중 상태**:
- 텍스트: "팔로잉"
- 배경색: 흰색 또는 회색 (`#8e8e8e`)
- 텍스트 색상: `#262626` (흰색 배경) 또는 흰색 (회색 배경)
- 테두리: 회색 (`#dbdbdb`)
- Hover: "언팔로우" 텍스트 표시, 빨간 테두리 (`#ed4956`)

**로딩 상태**:
- 버튼 비활성화
- 스피너 또는 "처리 중..." 텍스트

#### 2-3. 동작 흐름

```
사용자 클릭 → Optimistic UI 업데이트 (버튼 상태 변경)

→ 성공 시 콜백 호출 (통계 업데이트)
```

- 중복 팔로우: 에러 메시지 표시 (서버에서 방지)
- 인증 실패: 로그인 페이지로 리다이렉트 또는 안내 메시지
