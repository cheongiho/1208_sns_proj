# 게시물 상세 모달 개발 계획

## 개요

PRD.md의 게시물 상세 모달 요구사항과 기존 컴포넌트 구조를 기반으로 게시물 상세 모달을 구현합니다. Desktop에서는 모달 형식으로, Mobile에서는 전체 페이지로 전환되며, 댓글 전체 목록과 이전/다음 게시물 네비게이션을 지원합니다.

## 현재 상태

- ✅ Dialog 컴포넌트: shadcn/ui Dialog 컴포넌트가 구현되어 있음 ([components/ui/dialog.tsx](components/ui/dialog.tsx))
- ✅ PostCard 컴포넌트: 게시물 카드 UI가 구현되어 있음 ([components/post/PostCard.tsx](components/post/PostCard.tsx))
- ✅ CommentList 컴포넌트: 댓글 목록 컴포넌트가 구현되어 있음 ([components/comment/CommentList.tsx](components/comment/CommentList.tsx))
- ✅ CommentForm 컴포넌트: 댓글 작성 폼이 구현되어 있음 ([components/comment/CommentForm.tsx](components/comment/CommentForm.tsx))
- ✅ 댓글 조회 API: GET /api/comments가 구현되어 있음 (limit 파라미터로 전체 조회 가능)
- ❌ 게시물 단일 조회 API: 아직 구현되지 않음 (필요)

## 구현할 항목

### 1. API 라우트 구현

#### 1-1. 게시물 단일 조회 API
**파일**: `app/api/posts/[postId]/route.ts` (새 파일 생성)

- 동적 라우트로 개별 게시물 조회 처리
- URL 파라미터에서 `postId` 추출
- 게시물 정보 조회 (posts 테이블)
- 사용자 정보 조회 (users 테이블)
- 통계 정보 조회 (post_stats 뷰 또는 직접 계산)
- 인증된 사용자의 좋아요 상태 확인 (isLiked)
- PostWithUserAndStats 형식으로 응답 반환
- 에러 처리 (게시물 없음, DB 에러 등)

**참고 패턴**: [app/api/posts/route.ts](app/api/posts/route.ts)의 GET 함수 구조를 참고

### 2. PostModal 컴포넌트 구현

#### 2-1. 기본 구조
**파일**: `components/post/PostModal.tsx` (새 파일 생성)

- Client Component (`'use client'`)
- Props: `postId: string`, `isOpen: boolean`, `onClose: () => void`
- Dialog 컴포넌트 사용 (shadcn/ui)
- 반응형 레이아웃:
  - Desktop (≥1024px): 모달 형식
  - Mobile (<1024px): 전체 페이지로 전환 (또는 모달 전체 화면)

#### 2-2. Desktop 레이아웃 (모달 형식)
```
┌────────────────────────────────────────────────────────┐
│ ✕                                              ‹   ›   │
├──────────────────────────┬─────────────────────────────┤
│                          │ 👤 username          ⋯     │
│                          ├─────────────────────────────┤
│        [이미지]           │                             │
│        (50% 너비)        │      [댓글 목록]             │
│        (1:1 비율)        │      (50% 너비)              │
│                          │      (스크롤 가능)            │
│                          │                             │
│                          ├─────────────────────────────┤
│                          │ ❤️ 💬 ✈️            🔖      │
│                          │ 좋아요 123개                 │
│                          │ username 캡션...            │
│                          ├─────────────────────────────┤
│                          │ 😊 댓글 달기...       게시   │
└──────────────────────────┴─────────────────────────────┘
```

**구성 요소**:
- 좌측: 이미지 영역 (50% 너비, 1:1 정사각형)
- 우측: 댓글 영역 (50% 너비)
  - 헤더: 사용자명, 시간, ⋯ 메뉴
  - 댓글 목록: 전체 댓글 표시 (스크롤 가능)
  - 액션 버튼: 좋아요, 댓글, 공유, 북마크
  - 좋아요 수, 캡션
  - 댓글 작성 폼

#### 2-3. Mobile 레이아웃 (전체 페이지)
- 모달 대신 전체 페이지로 표시
- 또는 모달을 전체 화면으로 확장
- Instagram 앱과 유사한 UX

#### 2-4. 닫기 버튼
- 우측 상단 ✕ 버튼
- Dialog의 기본 닫기 버튼 사용
- ESC 키로도 닫기 가능

#### 2-5. 이전/다음 게시물 네비게이션 (Desktop)
- 좌측/우측 화살표 버튼 (‹ ›)
- 현재 게시물의 이전/다음 게시물로 이동
- 게시물 목록에서 현재 게시물의 인덱스 확인
- 첫 번째/마지막 게시물에서는 해당 방향 버튼 비활성화
- 키보드 네비게이션 지원 (← → 화살표 키)

**구현 방법**:
- PostFeed에서 게시물 목록을 props로 전달
- 또는 현재 게시물 ID를 기준으로 이전/다음 게시물 조회 API 호출

### 3. 게시물 상세 정보 로드

#### 3-1. 데이터 페칭
- PostModal이 열릴 때 게시물 상세 정보 조회
- GET /api/posts/[postId] API 호출
- 로딩 상태 표시 (Skeleton UI)
- 에러 처리 (게시물 없음, 네트워크 에러 등)

#### 3-2. 댓글 전체 목록 조회
- GET /api/comments?postId={postId}&limit={큰 수} API 호출
- 또는 limit 없이 전체 조회 (API 수정 필요할 수 있음)
- CommentList 컴포넌트에 `showAll={true}` 전달
- 댓글 목록 스크롤 가능 영역

### 4. PostCard 통합

#### 4-1. PostCard 클릭 이벤트
**파일**: `components/post/PostCard.tsx`

- 이미지 클릭 시 PostModal 열기
- 또는 "댓글 N개 모두 보기" 버튼 클릭 시 PostModal 열기
- PostModal에 현재 게시물 ID 전달
- 모달 열림 상태 관리 (상위 컴포넌트 또는 Context)

#### 4-2. 상태 관리
- PostFeed 또는 상위 컴포넌트에서 모달 상태 관리
- 선택된 게시물 ID 상태
- 게시물 목록을 PostModal에 전달 (이전/다음 네비게이션용)

### 5. 반응형 처리

#### 5-1. Desktop (≥1024px)
- 모달 형식: 중앙 정렬, 최대 너비 제한
- 좌우 분할 레이아웃 (이미지 50% + 댓글 50%)
- 이전/다음 네비게이션 버튼 표시

#### 5-2. Tablet (768px ~ 1023px)
- 모달 형식 유지 또는 전체 화면 모달
- 레이아웃 조정 (세로 스택 또는 유지)

#### 5-3. Mobile (<768px)
- 전체 페이지로 전환 (라우팅 또는 전체 화면 모달)
- 세로 스택 레이아웃 (이미지 위, 댓글 아래)
- 이전/다음 네비게이션 버튼 제거 또는 터치 제스처로 대체

### 6. 데이터 흐름 및 상태 관리

#### 6-1. 모달 열기 흐름
```
PostCard 이미지 클릭 → PostModal 열기 (postId 전달)
→ GET /api/posts/[postId] 호출 → 게시물 정보 로드
→ GET /api/comments?postId={postId} 호출 → 댓글 전체 목록 로드
→ PostModal 렌더링
```

#### 6-2. 댓글 작성/삭제 시 업데이트
- PostModal 내부에서 댓글 작성/삭제 시 댓글 목록 즉시 업데이트
- Optimistic UI 적용
- 댓글 수 실시간 업데이트

#### 6-3. 이전/다음 게시물 네비게이션
```
이전/다음 버튼 클릭 → 새로운 postId로 변경
→ PostModal 내부 상태 업데이트
→ 새로운 게시물 정보 및 댓글 목록 조회
→ 로딩 상태 표시 후 렌더링
```

### 7. 에러 처리 및 사용자 경험

- 게시물 없음: 404 에러 처리, 사용자 친화적 메시지
- 네트워크 에러: 재시도 버튼 제공
- 로딩 상태: Skeleton UI 또는 스피너
- 빈 댓글: "댓글이 없습니다" 메시지
- 키보드 네비게이션: ESC (닫기), ← → (이전/다음)

## 주의사항

1. **성능**: 게시물 상세 정보와 댓글 목록을 병렬로 조회하여 로딩 시간 최소화
2. **메모리**: 댓글이 많은 경우 가상 스크롤링 고려 (선택적)
3. **접근성**: 키보드 네비게이션, ARIA 레이블, 포커스 관리
4. **반응형**: 모든 화면 크기에서 정상 작동 확인
5. **모바일 UX**: 전체 페이지 전환 시 뒤로 가기 버튼 지원
6. **이전/다음 네비게이션**: 게시물 목록이 없는 경우 (직접 URL 접근) 처리

## 추가 고려사항

### Mobile 전체 페이지 전환 방법

**옵션 1: 라우팅 사용**
- `/post/[postId]` 동적 라우트 생성
- PostCard 클릭 시 라우터로 이동
- 장점: URL 공유 가능, 브라우저 뒤로 가기 지원
- 단점: 페이지 전환 애니메이션 제어 어려움

**옵션 2: 전체 화면 모달**
- 모달을 전체 화면으로 확장
- 상태 관리로 모달 열기/닫기
- 장점: 부드러운 전환, 상태 관리 용이
- 단점: URL 공유 불가 (추가 구현 필요)

**권장**: 옵션 2 (전체 화면 모달) - Instagram 앱과 유사한 UX

### 댓글 무한 스크롤

- 댓글이 많은 경우 (100개 이상) 무한 스크롤 고려
- 현재는 limit 파라미터로 제한
- 필요 시 댓글 페이지네이션 API 추가

### 이미지 최적화

- Next.js Image 컴포넌트 사용
- Lazy loading 적용
- 적절한 sizes 속성 설정
