# 홈 피드 페이지 개발 계획

## 1. API Route 구현

### 1.1 `app/api/posts/route.ts` 생성
- GET 메서드: 게시물 목록 조회
- 쿼리 파라미터:
  - `limit`: 페이지당 게시물 수 (기본값: 10)
  - `offset`: 건너뛸 게시물 수 (기본값: 0)
  - `userId`: 특정 사용자의 게시물만 조회 (선택, 프로필 페이지용)
- 정렬: `created_at DESC` (시간 역순)
- 데이터 조회:
  - `post_stats` 뷰 사용하여 좋아요 수, 댓글 수 포함
  - `users` 테이블과 JOIN하여 사용자 정보 포함
  - `PostWithUserAndStats` 타입 반환
- 응답 형식:
  ```typescript
  {
    data: PostWithUserAndStats[];
    hasMore: boolean;
    total?: number;
  }
  ```
- Supabase 클라이언트: `createClerkSupabaseClient()` 사용 (서버 사이드)

### 1.2 댓글 조회 로직
- 각 게시물의 최신 댓글 2개 조회
- `comments` 테이블과 `users` 테이블 JOIN
- `CommentWithUser` 타입으로 반환
- API 응답에 포함하거나 별도 API로 분리 (성능 고려)

### 2.4 액션 버튼 영역 (48px 높이)
- 좋아요 버튼 (좌측 첫 번째)
  - 빈 하트 ↔ 빨간 하트 아이콘

  - 좋아요 기능은 추후 구현 (현재는 UI만)
- 댓글 버튼 (좌측 두 번째)
  - MessageCircle 아이콘
  - 클릭 시 댓글 입력창 포커스 또는 상세 모달 열기
- 공유 버튼 (좌측 세 번째)
  - Send 아이콘
  - 1차 MVP 제외이지만 UI는 준비
- 북마크 버튼 (우측)
  - Bookmark 아이콘
  - 1차 MVP 제외이지만 UI는 준비
- lucide-react 아이콘 사용: `Heart`, `MessageCircle`, `Send`, `Bookmark`

### 2.7 댓글 미리보기

- 형식: "댓글 15개 모두 보기" (댓글이 2개 이상인 경우)

- `useState`로 게시물 목록 및 페이지 상태 관리

- `hasMore` 플래그로 더 이상 로드할 게시물이 없는지 확인

### 4.5 데이터 페칭
