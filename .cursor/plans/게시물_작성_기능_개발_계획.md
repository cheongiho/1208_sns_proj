# 게시물 작성 기능 개발 계획

## 개요

PRD.md의 게시물 작성 요구사항과 기존 컴포넌트 구조를 기반으로 게시물 작성 기능을 구현합니다. CreatePostModal 컴포넌트를 생성하고, 이미지 업로드 및 게시물 생성 API를 구현하며, Sidebar와 통합합니다.

## 현재 상태

- ✅ 데이터베이스: `posts` 테이블이 생성되어 있음 ([supabase/migrations/db.sql](supabase/migrations/db.sql))
- ✅ Storage 버킷: `posts` 버킷이 생성되어 있음 (공개 읽기, 5MB 제한, 이미지 파일만)
- ✅ 타입 정의: `Post`, `PostWithUserAndStats` 타입이 정의되어 있음 ([lib/types.ts](lib/types.ts))
- ✅ Dialog 컴포넌트: shadcn/ui Dialog 컴포넌트가 구현되어 있음 ([components/ui/dialog.tsx](components/ui/dialog.tsx))
- ✅ Sidebar: "만들기" 버튼이 있고 `showCreateModal` 상태가 준비되어 있음 ([components/layout/Sidebar.tsx](components/layout/Sidebar.tsx))
- ✅ Supabase 클라이언트: `useClerkSupabaseClient` 훅이 구현되어 있음 ([lib/supabase/clerk-client.ts](lib/supabase/clerk-client.ts))
- ❌ CreatePostModal 컴포넌트: 아직 구현되지 않음
- ❌ POST API: 게시물 생성 API가 아직 구현되지 않음

## 구현할 항목

### 1. API 라우트 구현

#### 1-1. 게시물 생성 API
**파일**: `app/api/posts/route.ts` (기존 GET 함수에 POST 함수 추가)

- POST 메서드로 게시물 생성 처리
- Clerk 인증 검증 (`auth()` 사용)
- 요청 본문에서 `imageUrl`, `caption` 파싱
- `caption` 유효성 검증 (최대 2,200자)
- Clerk user ID를 Supabase user_id로 변환 (users 테이블 조회)
- posts 테이블에 게시물 삽입
- 생성된 게시물과 사용자 정보를 포함한 응답 반환
- 에러 처리 (인증 실패, 사용자 없음, DB 에러 등)

**요청 형식**:
```typescript
POST /api/posts
Content-Type: multipart/form-data 또는 application/json
{
  "imageUrl": "https://...", // Supabase Storage URL (클라이언트에서 업로드 후 전달)
  "caption": "게시물 캡션..." // 선택적, 최대 2,200자
}
```

**또는 FormData 형식**:
```typescript
POST /api/posts
Content-Type: multipart/form-data
FormData:
  - image: File
  - caption: string
```

**응답 형식**:
```typescript
{
  success: true,
  data: PostWithUserAndStats
}
```

**구현 방식 선택**:
- **옵션 1**: 클라이언트에서 이미지 업로드 → 서버에서 게시물 생성 (권장)
  - 장점: 서버 부하 감소, 업로드 진행률 표시 용이
  - 단점: 클라이언트 코드 복잡도 증가
- **옵션 2**: 서버에서 이미지 업로드 + 게시물 생성
  - 장점: 서버에서 모든 검증 가능
  - 단점: 서버 부하 증가, FormData 처리 필요

**권장**: 옵션 1 (클라이언트에서 업로드 후 서버에서 게시물 생성)

**참고 패턴**: [app/api/comments/route.ts](app/api/comments/route.ts)의 POST 함수 구조를 참고

### 2. CreatePostModal 컴포넌트 구현

#### 2-1. 기본 구조
**파일**: `components/post/CreatePostModal.tsx` (새 파일 생성)

- Client Component (`'use client'`)
- Props: `isOpen: boolean`, `onClose: () => void`, `onPostCreated?: (post: PostWithUserAndStats) => void`
- Dialog 컴포넌트 사용 (shadcn/ui)
- Instagram 스타일의 모달 UI

#### 2-2. 레이아웃 구조
```
┌────────────────────────────────────────────┐
│ 새 게시물 만들기                    ✕      │
├────────────────────────────────────────────┤
│                                            │
│        [이미지 미리보기 영역]                │
│        (1:1 정사각형 또는 원본 비율)         │
│                                            │
│        또는                                │
│                                            │
│        [이미지 선택 버튼]                    │
│        사진을 선택하세요                    │
│                                            │
├────────────────────────────────────────────┤
│ 캡션 입력                                  │
│ ┌──────────────────────────────────────┐ │
│ │ 게시물에 대한 설명을 입력하세요...      │ │
│ │                                        │ │
│ │                                        │ │
│ └──────────────────────────────────────┘ │
│ 0 / 2,200                                  │
├────────────────────────────────────────────┤
│                    [공유하기]               │
└────────────────────────────────────────────┘
```

#### 2-3. 구성 요소

**1단계: 이미지 선택**
- 파일 선택 버튼 또는 드래그 앤 드롭 영역
- 이미지 파일만 허용 (accept="image/*")
- 파일 크기 검증 (최대 5MB)
- 이미지 미리보기 (선택 후)
- 이미지 변경 버튼 (다른 이미지 선택)

**2단계: 캡션 입력**
- Textarea 입력 필드
- Placeholder: "게시물에 대한 설명을 입력하세요..."
- 최대 2,200자 제한
- 실시간 글자 수 표시 (0 / 2,200)
- 선택적 (빈 값 허용)

**3단계: 업로드**
- "공유하기" 버튼
- 로딩 상태 표시
- 업로드 진행률 표시 (선택적)

#### 2-4. 이미지 업로드 로직

**클라이언트 사이드 업로드**:
1. 파일 선택 또는 드래그 앤 드롭
2. 파일 검증 (크기, 타입)
3. 이미지 미리보기 생성 (URL.createObjectURL)
4. "공유하기" 클릭 시:
   - `useClerkSupabaseClient` 훅 사용
   - 파일 경로: `{clerk_id}/{timestamp}-{random}.{ext}`
   - Supabase Storage에 업로드 (`posts` 버킷)
   - 업로드 성공 시 Public URL 획득
   - POST /api/posts API 호출 (imageUrl, caption 전달)
   - 성공 시 모달 닫기 및 콜백 호출

**파일 경로 형식**:
```
{clerk_id}/{timestamp}-{random}.{ext}
예: user_abc123/1704067200000-a1b2c3.jpg
```

**에러 처리**:
- 파일 크기 초과: "이미지는 5MB 이하여야 합니다"
- 파일 타입 오류: "이미지 파일만 업로드할 수 있습니다"
- 업로드 실패: "이미지 업로드에 실패했습니다"
- 게시물 생성 실패: "게시물 작성에 실패했습니다"

#### 2-5. 사용자 경험

- **드래그 앤 드롭**: 이미지 파일을 모달에 드래그하여 업로드
- **이미지 미리보기**: 선택한 이미지 즉시 표시
- **로딩 상태**: 업로드 중 버튼 비활성화, 스피너 표시
- **성공 피드백**: 업로드 성공 시 모달 닫기, 피드 새로고침 (선택적)
- **에러 피드백**: 사용자 친화적 에러 메시지 표시

### 4. 데이터 흐름 및 상태 관리

#### 4-1. 게시물 작성 흐름
```
사용자 클릭: "만들기" 버튼
→ CreatePostModal 열기
→ 이미지 파일 선택
→ 이미지 미리보기 표시
→ 캡션 입력 (선택적)
→ "공유하기" 클릭
→ 이미지 업로드 (Supabase Storage)
→ POST /api/posts 호출 (imageUrl, caption)
→ 성공 시 모달 닫기
→ 피드 새로고침 또는 새 게시물 추가
```

#### 4-2. 이미지 업로드 흐름
```
파일 선택 → 파일 검증

→ useClerkSupabaseClient로 Storage 업로드

→ POST /api/posts 호출
```

#### 4-3. 에러 처리 흐름
```
업로드 실패 → 에러 메시지 표시
→ 사용자가 재시도 또는 취소
→ 게시물 생성 실패 → 에러 메시지 표시
→ 사용자가 재시도 또는 취소
```

## 주의사항

1. **파일 크기 제한**: 5MB 초과 시 업로드 거부
2. **파일 타입 제한**: 이미지 파일만 허용 (JPEG, PNG, WebP)
3. **인증**: 모든 API에서 Clerk 인증 확인
4. **에러 처리**: 네트워크 에러, 업로드 에러, DB 에러 등 모든 경우 처리
5. **이미지 미리보기**: 메모리 누수 방지를 위해 URL.revokeObjectURL 호출
6. **파일 경로**: Clerk user ID를 폴더명으로 사용하여 사용자별 파일 분리
7. **Public URL**: Storage 업로드 후 Public URL 획득하여 DB에 저장
